# 内部设计历史

统一文档站不意味着我们要丢掉旧的设计沉淀，但这些内部历史材料现在默认不进入公开文档站，也不会同步到公开 docs 仓库。

## 1. 这里保存的是什么

- 私有的设计规格、实施计划、阶段性推进记录。
- 它们依然存在于内部工作区里，但不再是公开站点的一部分。

## 2. 这些历史材料的用途

它们主要用于：

- 回答“这个设计为什么会变成现在这样”。
- 帮维护者理解某些 contract 或 runtime state 的演化背景。
- 在继续扩展系统时，避免重复踩已经讨论过的问题。

## 3. 应该如何阅读

如果你只想理解当前系统，不需要先读这些历史文件。它们更适合：

- 要做大改动前的背景调查
- 追溯某个设计决策
- 对照当前实现和旧 spec 的偏差

## 4. 当前策略

- `docs/`：描述“现在系统是什么、怎么工作”。
- 私有内部历史：保留“系统为什么演化成这样”，但不公开发布。
- `DOC/`：仅保留兼容入口和旧链接提示。
